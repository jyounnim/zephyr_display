# Zephyr Display Labs — Synaptics SR110 (sr100_rdk/sr100/m55)

Synaptics **SR110** 보드(`sr100_rdk/sr100/m55`, Zephyr RTOS)에서 I2C/SPI 디스플레이를 하나씩 붙여가며 배우는 강의/워크샵용 실습 시리즈입니다. 원래 ESP32-S3-DevKitC-1용으로 작성됐던 실습을 SR110으로 포팅하면서, 두 플랫폼의 차이(핀먹스 고정 여부, I2C 드라이버 프로빙 방식, GPIO I/O 전압 도메인 등)를 실기로 검증하며 정리했습니다.

모든 실습은 **실기로 동작 확인이 끝난 상태**입니다.

## 진행 순서

01 → 02 → 03 (I2C) → 04 (SPI 기초) → 05 → 06 → 07 → 08 (SPI 디스플레이) 순서를 권장합니다. 각 문서 마지막의 "다음" 절이 이 순서를 안내합니다.

## SR110 관련 핵심 교훈 (전체 실습 공통)

포팅 과정에서 실기로 확인된, 이 보드에 특히 중요한 사실들입니다 — 새 디바이스를 붙일 때 참고하십시오.

- **전원**: 보드 헤더의 3.3V/1.8V 레일은 온보드 부품과 공유되어 있어, 외부 디바이스에 전원을 공급할 때 간헐적 오동작이나 write 실패의 원인이 될 수 있습니다. 가능하면 항상 외부 전원을 우선 사용하십시오 (01번 랩 문서 참고).
- **I2C 프로빙 방식**: SR110(`snps,designware-i2c`)에서는 zero-length/dummy write 프로빙이 아니라 **1바이트 read 프로빙**을 써야 디바이스를 놓치지 않습니다 — ESP32-S3와 정반대입니다 (01번 랩 문서 참고).
- **SPI0/콘솔 UART 충돌**: SR110의 유일한 SPI 마스터(SPI0)의 MOSI/MISO/CLK/CS가 보드 기본 콘솔(UART1)·UART0 기본 핀과 물리적으로 겹칩니다. SPI0을 쓰는 모든 실습(04~08)은 콘솔을 UART0의 대체 핀(J24 13/14번 핀)으로 옮깁니다 (04번 랩 문서 참고).
- **SPI0 하드웨어 FIFO는 8바이트뿐**: 8바이트를 넘는 단일 SPI 전송은 FIFO 재충전 인터럽트가 필요한데, 이게 이 플랫폼에서 안정적으로 안 걸려서 `-ETIMEDOUT`으로 실패합니다. raw SPI로 새 디바이스를 포팅할 때는 항상 전송을 8바이트 단위로 쪼개십시오 (06번 랩 문서 참고).
- **GPIO 재사용은 pinctrl 파일까지 확인**: 회로도 넷 이름만 보고 "안 쓰는 핀 같다"고 판단하면 위험할 수 있습니다 — 일부 핀은 JTAG나 디버그 모듈과 물리적으로 같은 패드를 공유합니다. 새 GPIO를 고를 땐 SDK의 `sr100_pinctrl.dtsi`로 해당 핀의 전체 alternate-function 그룹을 확인하고, 배선 전에 먼저 빌드/플래시해서 보드가 정상 부팅하는지부터 확인하십시오 (03번 랩 문서 참고).
- **GPIO I/O 전압은 1.8V**: 헤더에 3.3V 전원 핀이 있다고 해서 GPIO 로직 레벨도 3.3V인 건 아닙니다. SR110의 SPI0/GPIO 신호는 1.8V I/O 도메인입니다 — 3.3V IOVCC 사양의 디스플레이를 연결할 땐 레벨 시프터가 필요할 수 있습니다 (06번 랩 문서 참고).

## 개발 환경

- Zephyr RTOS (SDK: `syna_zephyr_sdk-1.0.0`)
- 보드 타겟: `sr100_rdk/sr100/m55`
- 빌드: `west build -p always -b sr100_rdk/sr100/m55 <실습 경로>/lab/`
- 플래시: `srsdk_tools/openocd_flash.py` (각 실습 문서의 "Build & Run" 절 참고)

## 회로도/데이터시트 참고

- SR110 RDK 회로도: `SC950-C01116-01 RevE`
- 각 실습 문서에 시트 번호와 함께 근거를 명시했습니다 (예: "10번 시트, PIN HEADERS")
